# 바둑 첫걸음 기획서

- 작성일: 2026-11-12
- 버전: 0.2 (2단계까지 반영. 결정 내용은 `docs/결정사항.md` 참고)
- 가칭: 바둑 첫걸음

## 1. 한 줄 정의

바둑을 한 번도 안 둬 본 사람이, 짧은 설명과 직접 두어 보는 문제를 따라가다 보면 **9줄 판에서 한 판을 끝까지 두고 스스로 집을 셀 수 있게 되는** 학습 웹앱.

## 2. 대상과 목표

### 대상
- 1차 대상: 규칙을 전혀 모르는 입문자. 초등 3학년이 혼자 읽고 따라 할 수 있는 말투와 분량을 기준으로 한다.
- 함께 쓰는 사람: 가족(초등 중학년, 초등 고학년, 중학생, 어른). 한 기기에서 여러 명이 각자 진행도를 갖는다.
- 대상이 아닌 사람: 이미 대국을 두는 급수자. 정석, 포석 이론, 고급 사활은 범위 밖이다.

### 학습 목표 (완주 기준)
1. 활로를 세고, 단수와 따내기를 알아본다.
2. 둘 수 없는 곳(착수금지)과 패를 구별한다.
3. 집과 공배를 구별하고, 끝난 판의 집을 센다.
4. 두 집이 있어야 산다는 것을 이해하고 기초 사활 문제를 푼다.
5. 축, 장문, 환격 같은 기본 기술을 한 번씩 써 본다.
6. 9줄 판에서 상대(가족 또는 쉬운 인공지능)와 한 판을 끝까지 두고 계가한다.

### 성공 기준
- 한 차시 5~10분. 설명 화면 하나에 글은 세 문장 이내.
- 설명만 읽고 넘어가는 차시가 없다. 모든 차시에 직접 돌을 놓는 활동이 들어간다.
- 인터넷 없이 열리고, 휴대폰 세로 화면에서 한 손으로 조작된다.

## 4. 용어 원칙

- 한국식 용어를 쓴다: 활로, 단수, 따내기(따냄), 착수금지, 패, 팻감, 집, 공배, 계가, 덤, 사활, 두 집(눈), 옥집, 빅, 양단수, 축, 축머리, 장문, 환격, 촉촉수, 수상전, 귀·변·중앙, 화점.
- 처음 나올 때는 쉬운 말로 풀어 준다. 예: "활로(돌의 숨구멍)", "단수(활로가 하나 남았어요)".
- 한자, 일본어, 영어 용어는 쓰지 않는다. 필요하면 용어 사전 화면에만 싣는다.
- 좌표는 가로 A~T(I 제외), 세로는 아래에서부터 1. 본문에서는 좌표보다 판 위 표시(세모, 동그라미)를 먼저 쓴다.

## 6. 기능

### 6.1 1차 범위 (꼭 넣는 것)
1. **바둑판**: 9줄, 13줄, 19줄. 누르면 돌이 놓이고, 놓인 돌을 누르면 활로가 보인다. 마지막 수, 단수, 패 자리를 표시한다.
2. **규칙 엔진**: 따내기, 착수금지, 패, 한 수 쉬기, 집 계산(집 + 따낸 돌 + 덤), 죽은 돌 지정.
3. **차시 화면**: 설명, 따라 두기, 퀴즈를 한 걸음씩 넘긴다.
4. **문제 유형 5가지**
   - 한 수 문제: 정답 자리에 두기
   - 수 세기: 활로 수, 집 수 고르기
   - 고르기: 둘 수 있다/없다, 살았다/죽었다, 보기 중 선택
   - 짚기: 판 위에서 조건에 맞는 돌이나 자리 누르기
   - 수순 문제: 내가 두면 상대가 정해진 대로 받는 여러 수 문제
5. **진행도 저장**: 기기 안에 저장(localStorage). 프로필 여러 개(가족용).
6. **연습 대국**: 9줄 2인 대국(한 기기에서 번갈아), 따내기 바둑, 쉬운 인공지능 상대.
7. **계가 도우미**: 끝난 판에서 죽은 돌을 눌러 고르면 집을 색칠해 세어 준다.
8. **용어 사전**: 배운 용어를 그림과 함께 다시 본다.

### 6.2 나중에 (1차 범위 밖)
- 강한 인공지능, 온라인 대국, 계정과 서버 저장, 기보 불러오기, 13줄과 19줄 전용 수업, 정석과 포석 이론.

### 6.3 아이 친화 원칙
- 터치 영역은 최소 44px. 9줄 판은 휴대폰 세로 화면에서 한 칸이 약 40px 이상이 되게 한다.
- 틀려도 벌점이 없다. "아쉬워요, 활로가 아직 남아 있어요"처럼 이유를 알려 주고 바로 다시 풀게 한다.
- 힌트는 2단계: 영역 표시 → 정답 자리 표시.
- 보상은 별과 배지 정도로 가볍게. 시간 제한, 순위표는 두지 않는다.
- 색만으로 구별하지 않는다(단수는 점선 테두리 + 문구).

| 종류 | 하는 일 | 자동 검산 |
| --- | --- | --- |
| `explain` | 설명 읽기 | 판 그림이 있을 수 있는 모양인지 |
| `free` | 정해진 수만큼 자유롭게 놓기 | |
| `explore` | 돌을 눌러 활로 보기 | 눌러 볼 덩어리 수 |
| `move` | 한 수 문제 | `check` 조건(capture, atari, escape, cut, connect)을 만족하는 수를 규칙 엔진으로 모두 찾아 `*` 자리와 같은지 비교 |
| `count` | 수 세기 | 표시한 돌의 실제 활로 수와 정답 비교 |
| `choice` | 고르기 | 이어짐 여부 문제는 실제로 이어졌는지 비교 |
| `point` | 짚기 | 귀·변·중앙·화점·단수 된 돌을 규칙으로 계산 |

예시 (4차시 따내기의 한 걸음)

```js
{
  type: 'move', check: 'capture',
  text: '흑 차례예요. 백돌의 마지막 활로를 막아서 따내 보세요.',
  right: '따냈어요! 따낸 돌은 나중에 내 점수가 돼요.',
  wrong: '아쉬워요. 백돌의 활로가 아직 남아 있어요.',
  hint: '백돌 옆에 비어 있는 점은 한 곳뿐이에요.',
  board: { rows: ['.....', '..X..', '.XO*.', '..X..', '.....'] },
}
```

- 글은 한 걸음에 세 문장까지. 넘으면 테스트가 실패한다.
- 별: 틀린 횟수와 힌트 사용 횟수의 합이 0이면 3개, 2 이하면 2개, 그보다 많으면 1개.
- 진행도 저장 형식 (localStorage `baduk-guide:v1`):

```json
{ "version": 1, "current": "p1", "profiles": [ { "id": "p1", "name": "이름", "color": 0, "done": { "L01": { "stars": 3 } }, "missions": { "capture-go": true }, "last": "L01" } ] }
```

## 9. 기술 구성

- **한 파일 웹앱**: `index.html` 하나에 화면, 스타일, 스크립트, 자료를 모두 담는다. 외부 글꼴, 라이브러리, 서버 요청이 없다. 파일을 그대로 열어도 동작한다.
- **개발 구조**: `src/`에 나눠서 쓰고 `node build.mjs`로 합친다.
  - `src/rules.mjs` 규칙 엔진 (화면과 무관한 순수 함수)
  - `src/lesson-engine.mjs` 판 그림 읽기, 문제 조건 계산, 차시 자료 검산
  - `src/lessons.mjs` 차시 자료
  - `src/ai.mjs` 쉬운 상대 "돌돌이"
  - `src/store.mjs` 프로필과 진행도 저장
  - `src/ui/board.js` 바둑판 그리기, `src/ui/app.js` 화면(홈, 차시, 따내기 바둑, 연습판, 프로필)
  - `src/style.css`, `src/index.template.html`
- **바둑판**: SVG. 줄 수와 화면 크기에 따라 자동으로 맞춰진다.
- **저장**: localStorage. 저장이 막힌 환경에서도 앱은 동작한다(저장만 안 됨).
- **쉬운 상대 "돌돌이"**: 규칙 기반. 따낼 수 있으면 따내고, 단수 된 돌은 달아나고, 스스로 단수가 되는 수와 자기 집 메우기는 피하고, 나머지는 가중치를 둔 무작위. 일부러 가끔 못 보고 지나친다(따내기 20%, 달아나기 45%). 같은 방식으로 두되 실수를 하지 않는 상대와 400판을 붙여 보면 돌돌이가 11% 이긴다. 실제 아이에게 맞는 세기인지는 직접 해 보고 조정한다.

## 12. 위험 요소와 대응

| 위험 | 대응 |
| --- | --- |
| 문제 자료에 틀린 정답이 섞임 | 빌드 때 규칙 엔진으로 자동 검산. 사활 문제는 작은 판에서 전수 탐색으로 한 번 더 확인 |
