# 회고: 바둑 첫걸음 v1.0 (2026-11-12)

비슷한 학습 웹앱(기타, 명화, 수학 등)을 만들 때 다시 볼 내용을 정리한다. 같은 내용을 본사 레포(aftermath-hq)에도 넘겼다.

## 1. 진행 순서 (하루 안에 0단계 → 배포)

| 단계 | 한 일 | 잘된 점 |
| --- | --- | --- |
| 0 기획 | 공식 규칙·입문 교재·기존 앱 조사, 기획서, 결정사항(항목마다 추천값) | 결정을 기다리느라 멈추지 않음. "진행해요" 한마디로 추천값 확정 |
| 1 뼈대 | 규칙 엔진 + 테스트 + 한 파일 연습판 | 엔진을 화면과 분리해서 뒤 단계가 쉬웠음 |
| 2 첫 단원 | 1단원 7차시 + 미션 + 프로필 + 쉬운 상대를 끝까지(세로로 한 줄) | 차시 틀이 굳은 뒤 나머지 단원은 자료만 쓰면 됨 |
| 3~5 | 나머지 17차시, 문제 묶음, 대국, 용어 사전, 새 디자인 | 자료 검산 테스트가 있어서 많이 써도 겁나지 않았음 |
| 6 배포 | 공개 전 점검 → 레포 공개 → GitHub Pages → 실제 주소에서 확인 | |

## 2. 다음에도 쓸 방법

1. **한 파일 오프라인 앱 구조**: `src/`에 모듈로 나눠 쓰고 `build.mjs`가 `import`/`export`를 걷어 내 한 스크립트로 합친다. 합칠 때 파일끼리 이름이 겹치는지 검사하고, 테스트가 "외부 자원을 부르지 않는지"를 확인한다.
2. **콘텐츠는 글자 그림, 정답은 엔진이 검산**: 판을 `'..X*.'` 같은 글자로 적고, 테스트가 모든 문제의 정답을 규칙 엔진으로 다시 계산해 자료와 비교한다. 185걸음을 써도 틀린 정답이 화면까지 간 적이 없다. 검산기 자체도 "틀린 자료를 잡아내는지" 테스트한다.
3. **문제 늘리기는 뒤집기와 색 바꾸기로**: 같은 모양을 좌우·상하로 뒤집거나 흑백을 바꿔 새 문제를 만들고, 뒤집은 판도 다시 검산한다.
4. **어려운 판정은 좁게 끝까지 읽기**: 사활은 둘러싸인 안쪽에서만, 축은 단수 치는 수만 따라가며 끝까지 읽는다. 전체 검산이 0.02초 안에 끝난다.
5. **쉬운 상대 세기는 숫자로 맞춘다**: 일부러 놓치는 확률(따내기 20%, 달아나기 45%)을 두고, 컴퓨터끼리 400판을 붙여 승률을 본다. 실제 아이에게 맞는지는 따로 확인해야 한다.
6. **화면 점검도 자동으로**: 같은 자료에서 정답 수순을 뽑아 브라우저에서 처음부터 끝까지 눌러 푼다(일부러 틀리기 포함). 한 번에 120초 안에 끝나도록 단원별로 나눠 돌린다.
7. **결정사항 문서**: 항목마다 추천값과 이유를 적고, 사용자가 정하면 날짜와 함께 바꾼다. 배포·레포 공개처럼 밖으로 드러나는 일은 따로 표시해 둔다.

## 3. 디자인에서 배운 것

- 단색 평면이 밋밋하다는 말에는 "층이 있는 배경 + 유리판 + 길 모양 학습 지도 + 캐릭터 표정"으로 답했다. 자세한 값과 출처는 `docs/디자인.md`.
- 유리판은 글자 대비가 가장 큰 위험이다. 판에 어두운 바탕색을 깔고, 흐림은 16px, 흐림을 못 쓰는 브라우저와 "투명도 줄이기" 설정에서는 불투명한 판으로 바꾼다.
- 맞음·틀림은 색만으로 알리지 않는다. 아래 영역 색 + 문구 + 캐릭터 표정을 함께 바꾼다.
- 같은 사용자의 다른 앱(기타 학습 앱)과는 뼈대(배경 층, 알갱이, 유리판, 알약 단추)만 맞추고 색은 주제에 맞게 따로 정했다.

## 4. 걸려 넘어진 것 (작업 도구)

| 상황 | 해결 |
| --- | --- |
| 브라우저 도구로 `file://` 주소를 열 수 없음 | `node -e`로 127.0.0.1에 작은 서버를 띄워 확인 |
| 같은 탭에서 화면 크기를 여러 번 바꾸면 스크린샷이 멈추거나 화면이 밀림 | 새 탭을 열어 다시 찍음 |
| REPL 코드 안에 `import`라는 글자가 있으면(문자열 안이어도) 실행이 막힘 | `'imp' + 'ort'`로 나눠 씀 |
| Node 26에서 `node --test tests/`가 실패 | 인자 없이 `node --test` |
| GitHub 푸시가 "email privacy"로 거절 | 레포의 작성자 메일을 GitHub noreply 주소로 바꾸고 커밋을 다시 만듦 |
| Slack 파일 올리기에 Buffer를 넘기면 실패 | Windows 경로 문자열을 넘김 |
| 크롬 북마크를 넣으려 했으나 데스크톱 앱 조작이 이 작업 방식에서는 막힘. REPL의 `chrome.bookmarks`는 Aside 브라우저의 북마크라 크롬과 다름 | 크롬은 켜져 있는 동안 북마크 파일을 직접 고치면 덮어씀. 사용자가 직접 추가하거나 데스크톱 조작이 되는 작업에서 처리 |
